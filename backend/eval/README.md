# Evaluation (Phase D)

This package replaces the deleted simulated script
(`scripts/evaluate_rag.py`, which fabricated scores from hardcoded
strings). Nothing here invents a quality number.

## Provenance

All corpus documents are self-written for this evaluation. They are
not copied from any publication, documentation site, or copyrighted
text. Product names (Qdrant, LangGraph, PostgreSQL, and so on) and
public facts about them (ports, default parameters) are used as
ordinary factual references, in the authors' own words. Topics were
chosen to be distinct enough that retrieval can be scored, with
deliberate near-collisions (for example, HNSW appears in both the
vector-database and Qdrant documents, but with different numbers) so
that a wrong-document answer is detectable.

Corpus: 10 documents (`corpus/corpus.json` lists exactly what is
ingested; `langgraph_source.txt` and `jwt-auth_source.txt` are
generator inputs, not corpus documents). Formats: `.txt`, `.md`,
`.pdf` (generated by the dependency-free writer in
`generate_corpus.py`, verified readable by pdfplumber), `.docx`
(generated with python-docx, already a production dependency).

Golden set: 55 answerable questions (`golden/golden.json`), each
with a source document and expected keywords; 16 unanswerable
probes (`golden/unanswerable.json`); 6 prompt-injection probes
(`golden/injection.json`) scored by a fixed forbidden-string rule.

## Runner

From `backend/`:

```bash
# Pipeline smoke test only. Fake hashed bag-of-words embeddings and
# a fake LLM that copies the best-overlapping context chunk. Proves
# ingest -> retrieve -> graph -> metrics -> output works. NOT a
# quality measurement; never quote its scores as system quality.
python eval/run_eval.py --mode offline

# Real evaluation. Needs a valid OPENAI_API_KEY in the environment
# (not a placeholder). Runs the real graph, real embeddings, and an
# LLM-as-judge at temperature 0 with a fixed rubric (see judge.py).
# Token/cost figures are tiktoken-based estimates, not metered usage.
OPENAI_API_KEY=... QDRANT_HOST=:memory: python eval/run_eval.py --mode live
```

Variants (only numbers from runs actually executed may be quoted):

```bash
python eval/run_eval.py --mode offline --variant threshold-off --threshold 0.0
python eval/run_eval.py --mode offline --variant no-mmr --no-mmr
```

Output goes to `docs/eval/<run-id>/summary.json` +
`results.jsonl`. Runs never overwrite earlier runs. Every record
carries a `mode` field (`offline-pipeline-smoke` or `live`).

## Metrics and their limits

- Retrieval: hit-rate@1/@3/@5 and MRR against the golden source doc.
- Citation precision: cited chunk ids that were actually retrieved
  / all cited ids (refusals excluded — they have no claims to cite).
- Faithfulness: hand-rolled sentence/token overlap against cited
  chunks. Coarse by design: it catches unsupported answers, not
  subtle hallucinations. RAGAS was not added (optional in the brief):
  hand-rolled with clear limits was preferred over a new dependency
  whose faithfulness score would itself need validation.
- Correctness, live: LLM-as-judge, fixed rubric, temperature 0;
  judge failures are recorded as `judge_error` and excluded, never
  counted as pass or fail. Correctness, offline: keyword overlap
  only, labelled as such.
- Refusal accuracy: fixed marker rule (see `metrics.py`).
- Injection pass rate: fixed forbidden-string rule per probe.
- Latency: p50/p95/mean over golden questions (search + graph).

## Extending

Add a document to `corpus/` and to `corpus.json`, add questions to
`golden/golden.json` with the document filename as
`source_document`, and re-run. To regenerate the binary corpus
files from their text sources: `python eval/generate_corpus.py`.
