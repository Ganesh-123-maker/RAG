# REST API Design: Resources, Status Codes, and Idempotency

A REST API exposes resources, each named by a URL, and manipulates them with HTTP methods. GET reads a resource and must never change server state. POST creates a subordinate resource. PUT replaces a resource entirely, while PATCH applies a partial update. DELETE removes a resource. A well-designed API keeps these meanings strict, because clients, caches, and proxies all rely on them: GET and PUT are safe to retry, POST is not.

Status codes are the API's vocabulary for outcomes. 200 OK means the request succeeded. 201 Created means a new resource was created, and the response should include a Location header pointing at it. 400 Bad Request means the client's input was invalid. 401 Unauthorized means authentication is missing or failed, while 403 Forbidden means the caller is authenticated but not allowed to do this. 404 Not Found means the resource does not exist. 409 Conflict means the request clashes with current state, such as creating a duplicate unique name. 500 Internal Server Error means the server failed, and the client should generally retry later rather than immediately.

Collections are paginated, never returned whole. The two common schemes are offset pagination (limit and offset query parameters, simple but unstable when rows are inserted mid-list) and cursor pagination (an opaque cursor pointing at the last seen item, stable under inserts and preferred for large or fast-changing lists). A list response should include the total count only when it is cheap to compute; counting millions of rows on every page is a common performance trap.

Idempotency is what makes retries safe. A client that retries a POST after a timeout can create the same resource twice unless the API supports idempotency keys: the client sends a unique key with the request, and the server stores the result keyed by it, returning the stored result instead of executing twice. Stripe popularized the pattern, and it is now standard for any payment or order-creation endpoint.
