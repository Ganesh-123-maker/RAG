Vector Databases: An Introduction

A vector database stores embeddings, which are lists of numbers that
represent the meaning of text, images, or other data. Items with similar
meanings have embeddings that point in similar directions, so similarity
search becomes a geometry problem: find the stored vectors closest to a
query vector.

Exact nearest-neighbour search compares the query against every stored
vector. That is accurate but slow once a collection grows. Approximate
nearest-neighbour search, usually shortened to ANN, trades a small amount
of accuracy for much greater speed. A well-tuned ANN index can return
results in milliseconds even for large collections.

The most widely used ANN method is HNSW, short for Hierarchical
Navigable Small World graphs. HNSW builds a layered graph. The upper
layers contain a few long-range links that let a search jump quickly
across the space, while the bottom layer contains dense local links.
A search starts at the top layer and greedily moves to closer neighbours
as it descends.

Two HNSW parameters control the trade-off between recall and speed.
The parameter M sets the maximum number of connections per node; a
typical value used in this guide is M equals 16. The parameter
efConstruction controls how thoroughly the graph is built; a typical
value used here is efConstruction equals 200. Larger values improve
recall but slow down indexing.

A worked example in this guide indexes 12 million product vectors and
measures recall of 0.97, meaning 97 out of 100 true nearest neighbours
are found, while answering queries in under 20 milliseconds. That
combination of scale, recall, and latency is why vector databases are
used for recommendation, duplicate detection, and retrieval-augmented
generation.

Vector databases also store metadata alongside each vector, called a
payload. A payload filter can restrict a search to one tenant, one
document, or one category before similarity ranking is applied. Without
payload filtering, a multi-tenant application would have to run a
separate collection per user, which wastes resources and complicates
operations.
