# Fine-Tuning Large Language Models

Fine-tuning adapts a pretrained model to a task or domain by continuing training on task-specific data. Full fine-tuning updates every weight in the model. It gives the most freedom but is expensive: a 7-billion-parameter model needs roughly 28 GB of memory just to hold the weights in 16-bit precision, plus optimizer state that can triple that, and it risks catastrophic forgetting, where the model loses general abilities it had before tuning.

Parameter-efficient fine-tuning (PEFT) updates only a small part of the model. The best-known method is LoRA, low-rank adaptation. LoRA freezes the pretrained weights entirely and injects small trainable matrices into the attention and feed-forward layers. Each injected update is the product of two low-rank matrices, A and B, whose inner dimension is the rank r. With r = 8, a layer that would have millions of trainable weights in full fine-tuning needs only a few ten-thousands of adapter weights. The scaling factor alpha, commonly set to 16, controls how strongly the adapter output is added to the frozen layer output: the update is multiplied by alpha / r.

At inference time the adapter can be merged back into the frozen weights, so a LoRA-tuned model runs at exactly the same speed as the base model, with no extra latency. Different adapters can be swapped in for different tasks while the base model stays untouched, which makes LoRA cheap to store -- an adapter is usually a few megabytes, against gigabytes for a full copy of the model.

Choosing between the two is a trade-off: full fine-tuning wins when the target task is far from the pretraining distribution and you have the compute; LoRA wins for most practical adaptation, especially when data is limited, because fewer trainable weights also means less overfitting. A common middle ground is to fine-tune with a low learning rate and early stopping, and to keep a held-out validation set to catch catastrophic forgetting before it ships.
